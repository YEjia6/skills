# 项目实现级文档

输入项目目录即可开始，默认读取该目录所在的当前工作树，输出至项目的 `docs/delivery/项目实现说明/`，可指定其他输出目录。先检查适用的仓库规则和工作树限制。只写交付目录，保留用户已有内容，遇到同名非本技能文档时使用独立子目录。引用配置时保留键名，隐去凭据和业务数据。

## 建立清单和基线

读取项目说明、构建清单、部署配置及目录结构。以模块注册、依赖声明和真实入口交叉盘点，涵盖页面、接口、命令、定时任务、消息消费者、数据库脚本和配置驱动入口。记录各入口发现依据；动态装载的范围无法确定时注明原因。为业务模块、公共组件、生成代码及外部依赖分别建行，给出分析边界和理由。内部生成入口仍须关联到功能及生成来源。

在覆盖清单中记录项目根、分支、提交和工作树状态。为分析范围内的源码、配置、测试和构建清单保存相对路径及内容摘要（SHA-256），包含相关未跟踪文件，排除交付目录和构建缓存。无版本库时同样使用文件摘要。沿真实引用建立“使用方依赖提供方”的模块图；将相互可达的模块合为一批，再从无未处理依赖的批次开始。

可用 [基线工具](scripts/baseline.py) 处理大清单。在 Python 3.11 及以上环境，将本次完整的项目相对路径列表逐行送入标准输入，执行 `python baseline.py 项目根目录 交付目录/基线.json`。首次盘点加 `--save`；恢复和终验时先比较，待所有受影响文档复核后才更新基线。缺少该运行环境时用本机摘要工具完成同一核对。

## 连续执行与恢复

按照[文档模板](references/templates.md)建立目录和覆盖清单，为模块、入口、功能和流程分配稳定标识。先记录批次为“进行中”，再写文档。逐个入口沿调用、消息或数据变更追到结果，记录分支触发条件、跨批次目标和证据。批内文档写完并核对后，最后更新清单为“已核对”，保存已覆盖入口、待接续的调用和未知项。直接处理下一批，直至没有待处理模块。

恢复时从磁盘读取清单和文档，对比当前路径及摘要。重新检查未完成批次与丢失的交付文件；复用稳定标识并更新对应章节，避免重复追加。对新增、删除、改名及内容变化的文件重新归属模块；复核受影响模块、反向依赖和引用这些模块的流程，更新架构和索引。归属不明或构建配置变动时重新盘点全图。最终交付前再次核对摘要；持续变化导致无法核验时保留待复核状态。

## 撰写与交付

关键断言标为“事实”“推断”或“未知”。事实附基线内的相对路径、行号和符号，推断列出前提，未知列出已查位置和缺失材料。运行结果、已有测试断言和人工推演分别标注。发现矛盾时并列记录实现、配置及测试各自表明的行为。外部服务只描述可观察契约。

使用[验收清单](references/acceptance.md)逐项核验，回填证据和未解决事项。总目录须能从功能索引到流程、模块实现及验证依据。所有批次核对且验收通过才标记完成；中断时交付可续跑的状态和下一批标识。
