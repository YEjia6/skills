# 交付前验收

1. 独立对照构建注册、目录和各类运行入口，与清单做双向核对。每个模块有结论或有依据的分类理由；每个业务入口关联到功能。新发现的内部入口补入相应批次。
2. 从总目录逐一检查交付链接、功能索引和源码引用。核实路径存在、行号对应符号、内容属于最终基线。测试缺失时记缺口，阅读断言与实际执行分别登记。
3. 选择跨模块流程逐跳核对两端、数据标识、状态变化、终态和异常路径。所有暂挂调用须已接续或归入有证据边界的未知项。
4. 对有边界分支的关键算法，用具体正常输入和边界输入对照实现逐步复算。若能在合适环境运行现有测试，记录命令及结果。没有相应流程或算法时登记盘点依据。
5. 检查批次状态、最终文件摘要及尚未解决的问题。记录已核对模块数、业务入口数、未知项数和覆盖范围。缺文档、失效引用、未归属的内部入口或未复核的变动均须修复后才能宣布完成。
